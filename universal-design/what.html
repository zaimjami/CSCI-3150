What universal design looks like in code, content, and structure

Definition (my short version)

Universal design means most people can use your site, in most situations, without special workarounds. It’s accessibility + usability + resilience: equitable, flexible, intuitive, forgiving, low-effort, and roomy enough for different inputs (mouse, touch, keyboard, voice) and contexts (sunlight, low bandwidth, motion sensitivity).

Plan before pixels: IA and language

  • Write the sitemap and task flows first; remove steps that don’t help users finish the job.
  • Use plain language. Replace “utilize/submit” with “use/send.” Microcopy is part of access.
  • Prototype headings as a table of contents; if the outline reads clearly, the UI will too.

Semantics before ARIA

  • Use header, nav, main, section, article, aside, footer for structure.
  • Use button for actions; a for navigation. Don’t make clickable divs.
  • Headings descend one level at a time. Don’t jump from h2 to h5.
  • Add ARIA only when HTML can’t express the thing (roving focus, composite widgets, live updates).

Readable, forgiving CSS

  • Contrast: AA minimum; AAA for small gray text. Validate against your palette.
  • Type: base 16px+, 1.5 line height, 50–75ch line length; never fully justify paragraphs.
  • Motion: provide a calm path using prefers-reduced-motion.
  • Dark/light: test both. Ensure contrast stays AA in each theme.

Responsive by default (Grid + Flexbox)

Use Grid for 2-D page layout and Flexbox for 1-D groups (navs, button rows, cards). Start mobile-first, then enhance at content-driven breakpoints. Test zoom at 200% and reflow — no sideways scroll for body text.

Forms that don’t fight users

  • Every control has a <label for>. Group related fields with fieldset/legend.
  • Use autocomplete tokens and inputmode. Surface errors inline with aria-describedby.
  • Don’t wipe the user’s input on error; explain how to fix it in regular language.

Content patterns

  • Alt text: describe the purpose, not the pixels. If it’s decorative, give it empty alt (alt="").
  • Links: “View pricing,” not “Click here.” Include context in the text itself.
  • Tables: add <caption>, mark header cells with <th scope>, and keep the reading order sane.
  • Media: captions and transcripts; avoid autoplay with sound.

Seven principles applied to the web

  1. Equitable use: same content, same path; no “alt” experience hidden in a PDF.
  2. Flexibility: mouse, keyboard, touch, voice all work end-to-end.
  3. Simple & intuitive: predictable components; no mystery meat navigation.
  4. Perceptible info: contrast + alternatives; never color-only signals.
  5. Tolerance for error: undo, confirm, autosave; forgiving validation.
  6. Low effort: big targets, minimal precision, fewer steps.
  7. Size & space: layouts breathe; tap zones aren’t crowded.

Robust widgets to reuse

  • Disclosure/accordion: toggle with Space/Enter; set aria-expanded and aria-controls.
  • Tabs: arrow keys move focus; aria-selected, tabindex roving, and aria-controls.
  • Menu button: opens on click/Down; closes on ESC/blur; returns focus to trigger.
  • Dialog: trap focus; restore focus on close; close on overlay/ESC; aria-modal="true".
