How to build it so it keeps working

Focus, targeting, and motion (the fast wins)

:where(a,button,[role="button"],input,select,textarea):focus-visible{
  outline:3px solid #e9c46a; outline-offset:2px; border-radius:.25rem;
}
.btn,.menu a{ min-width:44px; min-height:44px; padding:.6rem .85rem; }
@media (prefers-reduced-motion: reduce){
  *{animation:none !important; transition:none !important}
}

Don’t remove outlines globally. Replace them with something obvious and consistent.

Reading order and landmarks

  • DOM order = reading order. Visually re-arrange with CSS, not with random tab-indexing.
  • Use header, nav, main, aside, footer once per major region. Screen readers have landmark shortcuts; give them something to jump to.

Alt text that helps

  • Informational: “Priyanka Chopra and Ranbir Kapoor at a promo event.”
  • Functional: For a poster thumbnail linking to details, “Barfi! theatrical poster — open film details.”
  • Decorative: if it’s just flourish, alt="". Don’t describe the flourish.

Accessible forms (copy/paste baseline)

<fieldset>
  <legend>Contact</legend>

  <label for="email">Email</label>
  <input id="email" name="email" type="email" autocomplete="email"
         inputmode="email" required>

  <label for="msg">Message</label>
  <textarea id="msg" name="message" rows="6"
            aria-describedby="msg-help"></textarea>
  <p id="msg-help">Share as much detail as you like.</p>

  <button class="btn">Send</button>
</fieldset>

On error, keep the user’s input, focus the first invalid field, and explain how to fix it. Use plain language.

Custom components without the pain

Tabs (pattern sketch): roving tabindex on the tab list, arrow keys move focus, Enter/Space activates, set aria-selected on the active tab, each tab owns a role="tabpanel" via aria-controls. On activation, move focus into the panel only if that’s the expected behavior.

Dialog: trap focus while open, return focus to the invoker on close, close on ESC and overlay click, set aria-modal="true" and label with aria-labelledby.

Don’t reinvent these from scratch under a deadline. Either use a well-audited library or follow the ARIA Authoring Practices to the letter.

Media: do the complete job

  • Provide captions (not auto-captions only) and transcripts for long-form content.
  • Give users control: no autoplay with sound, and visible play/pause/seek buttons that work with a keyboard.
  • Describe meaningful on-screen text in the audio if it isn’t read aloud.

Testing that actually catches issues

  1. Automated pass: Nu validator (HTML), WAVE/axe (a11y), Lighthouse (a11y/perf). Fix the basics before manual testing.
  2. Keyboard pass: unplug the mouse. Can you reach every control? Is focus always visible? Can you close dialogs and menus with ESC?
  3. Screen reader pass: VoiceOver (Mac/iOS) or NVDA (Windows). Check the headings list, landmarks list, and links list. Do they read like a map?
  4. Zoom & reflow: 200% zoom and portrait/landscape. Body text should not require horizontal scrolling.
  5. Mobile pass: try with TalkBack (Android) and VoiceOver (iOS). Confirm rotor/quick nav can jump by headings and landmarks.

Keep it shippable: process and guardrails

  • Design tokens: pre-vetted color pairs (AA or better), spacing scale, focus styles, motion rules. Designers can’t pick illegal colors if they’re not in the tokens.
  • PR checklist: headings in order; controls are native or accessible; visible focus; labels; ARIA only where needed; reduced-motion respected.
  • Definition of Done: keyboard operable, contrast passes, zoom/reflow passes, linter and validator clean.
  • Docs: every component has “keyboard behavior” and “AT expectations” written down.

Anti-patterns to retire

  • Links that open new windows without warning.
  • Infinite carousels with no pause/stop and no semantics.
  • Placeholders used as labels; the label disappears when you type.
  • “Click here” links with no context; screen-reader users hear an identical list of “Click here.”
  • Removing outlines globally with outline: 0; and calling it “clean.”

Performance is part of access

  • Ship 2× fewer JS libraries than you think you need. Less script = faster input and less jank for everyone.
  • Compress and lazy-load media; always include intrinsic width/height to prevent layout shift (CLS).
  • Prefer system fonts or a tight subset; avoid FOIT, and provide font-display: swap.

Quick fixes that punch above their weight

  • Add a skip link before the header. It’s a one-liner that saves time every visit.
  • Make every interactive thing a real HTML control. You immediately gain keyboard and semantics.
  • Replace color-only states with icon + text + color.
  • Audit headings. Treat them like a table of contents.

Toolkit to keep around

  • Validators: W3C Nu (HTML), WAVE or axe DevTools (a11y), Lighthouse (a11y/perf).
  • Checkers: WebAIM contrast, Heading Map/HTML5-Outliner, CSS media feature emulators.
  • AT: VoiceOver (macOS/iOS), NVDA (Windows), TalkBack (Android). Learn two; you’ll catch different issues.
